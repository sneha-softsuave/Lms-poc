# Client Demo Runbook — Defense AI LMS

A full, presentable web UI with two roles (admin + learner). Follow this to run
the demo. It's already seeded with a sample published course, so there's content
the moment you open it.

## Prerequisites (one time)
- **Backend deps**: from the repo root — `python -m venv .venv`, activate, `pip install -r requirements.txt`
- **Frontend deps**: `cd frontend && npm install`
- **3D models**: from the repo root — `python scripts\generate_3d_models.py`
  (generates the 5 equipment GLBs the viewer displays; served locally, no CDN)
- **AI key**: your OpenAI key is set in the repo-root `.env` (`MODEL_PROVIDER=openai`). This powers
  the chatbot + course generation.

## Start (two terminals)

**Terminal 1 — backend** (repo root):
```powershell
.\.venv\Scripts\Activate.ps1
python scripts\seed_demo.py     # one-time: loads the sample course + demo learner
uvicorn app.main:app --reload
```
> First start takes ~15s — it indexes the course into the chatbot (via OpenAI embeddings).

**Terminal 2 — frontend** (`frontend/` folder):
```powershell
npm run dev
```
Open **http://localhost:3000**.

## Suggested demo script (~5 min)

**As the learner** (`cadet`):
1. **Course catalog** — shows the published course grouped by subject. Click **Continue**.
2. **Lesson view** — read a lesson; note the *source page* badge (provenance).
3. **Interactive 3D** tab — the "Assault rifles" lesson has a 3D model. Rotate/zoom it,
   then click a **component hotspot** → a grounded, cited explanation appears.
4. **Ask the tutor** (right panel) — type *"What is the effective range of the 5.56mm LMG?"*
   → grounded answer **with a citation**. Then ask *"What is the capital of France?"*
   → it **abstains** ("not covered") instead of guessing. This is the key trust story.
5. **Module quiz** tab — answer and submit → **auto-graded** with rationale + sources.
6. **My learning** — progress bar and resume point update as you complete lessons.

**As the admin** (`admin`):
1. **Overview** — document / draft / published / enrolment counts + engagement table.
2. **Materials & AI** — upload a PDF/DOCX (e.g. your `dkip_document_1.pdf`) → **Generate course**
   → the AI builds a draft (subject, modules, lessons, glossary, quiz) in ~30s.
3. **Courses & Review** — open the draft: edit lessons, **attach a 3D model**, **approve/reject**
   questions, then **Publish** (it can't publish while questions are pending).
4. **Analytics** — cohort progress, subject mastery, weakest topics.
5. **Audit log** — every chat / quiz / enrolment / publish recorded immutably.

## Talking points
- **Grounded + cited or it abstains** — never fabricates (the France question proves it).
- **Provider-swappable** — OpenAI today, Claude or a local air-gapped model tomorrow, by config only.
- **Human-in-the-loop** — AI drafts; an admin reviews and publishes.
- **Provenance everywhere** — lessons, glossary, quiz rationales and citations all trace to a page.

## Notes
- The 5 equipment models (rifle, engine, generator, field radio, utility vehicle) are real GLB meshes
  generated by `scripts/generate_3d_models.py` and served locally from `/media/models3d/` (no CDN).
  They're low-poly but recognizable; swap in higher-fidelity `.glb` files at the same paths any time.
  In the demo, the "Assault rifles" lesson has the rifle model attached — an admin can attach the
  others to any lesson from **Courses & Review**.
- Using **Qdrant** (via `docker compose up`) instead of the in-memory index makes restarts instant
  (no re-embedding on startup) and persists the index.
